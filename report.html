1. Project Purpose & Scope

The goal of this project is to construct a rigorous lexical analyzer using JFlex and Java that recognizes arithmetic expressions, identifiers, numeric literals, relational operators, delimiters, and comments. The system includes both a standard command-line interface (CLI) conforming to the specification and a modern JavaFX Graphical User Interface (GUI) featuring real-time token inspection, syntax diagnostics, an interactive DFA state tracer, and an automated 16-case benchmark runner.

Language Features In Scope:

  • Identifiers: [a-zA-Z_][a-zA-Z0-9_]* (e.g. total, qty, x1).
  • Numeric Literals: Non-negative integers 0 | [1-9][0-9]* and floating decimals (0 | [1-9][0-9]*)\.[0-9]+.
  • Operators: Assignment (=), Arithmetic (+, -, *, /, %, ^), and Comparison (>, >=, <, <=, ==, !=).
  • Delimiters: Parentheses (, ), statement terminators ;, and comma ,.
  • Comments: Single-line // ... and multi-line /* ... */ cleanly skipped.
  • Error Handling: Non-fatal error reporting with 1-based line and column positions. Scanning continues to EOF.

Features Outside Scope:

Syntax tree validation (AST parsing) and arithmetic expression evaluation are intentionally kept outside the lexical scope.

3. Competing Rules & JFlex Disambiguation Analysis

Case 1: Relational Operator >= vs > and =

Conflict: When encountering >=, rule ">" could match the first character, leaving "=" to be matched separately as an assignment.

Resolution: JFlex enforces the Longest Match (Maximal Munch) principle. The rule ">=" consumes 2 characters, whereas ">" consumes only 1. JFlex selects the 2-character match and emits a single OP_GTE token.

Case 2: Decimal 12.5 vs Integer 12

Conflict: The integer pattern matches 12 (length 2). The decimal pattern matches 12.5 (length 4).

Resolution: JFlex matches the full 4 characters as {Decimal} due to longest match precedence, correctly avoiding an integer match followed by an unexpected dot.

Case 3 (Bonus): Division Operator / vs Single-Line Comment //

Resolution: // starts a comment matching the full line (length > 2). The longest match principle ensures the entire comment is discarded without emitting spurious division operators.

5. Bug Discovery, Root Cause & Correction

Bug Description: In initial specifications, decimal was written as Decimal = {Integer} \. {Digit}*. When scanning x = 12. + 5;, 12. with zero fractional digits was incorrectly matched as a Decimal token.

Correction: We updated the pattern to Decimal = {Integer} \. {Digit}+ requiring at least one trailing digit. Now, 12 is scanned as INTEGER, . is rejected as an unexpected character with Line 1 Col 7, and + 5 continues cleanly. Recorded as test BUG01.
